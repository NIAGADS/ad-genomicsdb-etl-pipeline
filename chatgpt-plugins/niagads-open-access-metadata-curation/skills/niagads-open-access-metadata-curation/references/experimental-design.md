# Experimental design and file-to-analysis reconciliation

Build a working analysis inventory guided by the study and target files. Consider tested phenotypes (including composite endpoints), quantitative vs binary outcomes, cohort-level vs meta-analysis vs pooled individual-level results, population/ancestry, sex/genotype strata, interactions, alternative models and covariates, inclusion/exclusion criteria, frequency thresholds and variant/test classes. Preserve the meaning of the authors' definitions and distinguish measured, derived and proxy phenotypes. Do not assume all theoretical combinations were actually tested.

Use a compact table when useful: analysis identifier or description | tested phenotype | population/cohort | design/adjustment | N or cases/controls | target file | evidence | mapping status. Split tables or omit inapplicable columns for readability. Cite specific source locations for important details. Do not copy paper-wide N into subgroup files; distinguish participant totals, analyzed samples, per-variant sample sizes, discovery/replication, overlapping cohorts and controls. Only compute counts when inputs are explicitly supported and the operation is valid; report derivation and uncertainty. Do not treat ancestry as proof of race or ethnicity, or a stratification variable as proof of covariate adjustment.

Distinguish file-level mapping from study-wide context. File names and dictionary codes may support reconciliation but are not alone conclusive if ambiguous. Label mappings confirmed by curator, proposed, ambiguous or unmatched. Ask targeted questions and allow the curator to investigate the paper with you, provide file information or correct mappings. Do not require every paper analysis to map to a submitted file or vice versa. Reassess counts, traits and design if mappings change.

Before advancing, summarize the agreed mappings and unresolved items, request explicit confirmation of relevant analyses/files, and offer to advance to ontology annotation only for the confirmed scope. Do not initiate ontology annotation or JSON generation simply because the curator asked or answered a question.
